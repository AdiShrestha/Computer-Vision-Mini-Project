## Findings

**Evidence-backed**

1. **The archive is incomplete.** 85 of the 147 inventoried files are absent: all 80 `factory/` files, `LICENSE`, `.gitignore`, `bootstrap.sh`, `pytest.ini` and one `data/` file.
   - The README's test command fails on this bundle (`ModuleNotFoundError: sentinel_gl`). The cause is the missing `pytest.ini`, so this is not a project defect.
   - It does mean everything about the factory (302 tests, F25–F28, FU09–FU16) is verifiable only from logs. I could not inspect that code.
2. **`metrics.py` and `calibration.py` import torch and sklearn through `scoring.py`** (`from .scoring import finite_vector`, while `scoring.py` imports torch and `sklearn.decomposition` at lines 5–6).
   - This couples the evaluation layer to heavy dependencies. That conflicts with plan §9.2(4), which wants an independent metric verifier, and with the isolated-runtime problem in F26.
   - Moving the numpy-only helpers into their own module fixes it.
3. **Documents contradict each other.** `docs/VALIDATION.md` still advertises "Merkle root frozen file inventories" and signing-key receipts, while plan §15.3 says the field is not a Merkle tree and F27/FU10 say the receipt scheme was unsafe. Several files in `docs/` describe another project's AML-ring forensics, and only `MIGRATION.md` carries a "not Sentinel-GL" note. Nothing machine-enforces the "background only" rule.
4. **plan.md has two sources of truth.** §4.1 still describes the pre-follow-up core: the `metrics.py` row omits the `eligible` and `max_gap_days` parameters that FU07 made mandatory. §15 supersedes it, but only by addendum.
5. **§15.2 overstates the before-evidence.** It says baseline behavior is preserved in `before_counterexamples.json`, but that file covers 4 of 16 findings (FU01, 02, 03, 07). FU04, 05, 06 and 08 are core items with no preserved "before" state.
6. **Naming collision.** `TimeSeriesMAE.n_windows` (default 108) is the maximum number of time steps, while `features.Window` is a 180-row context. F16 already documented window/row confusion as a legacy failure, so this is a live hazard.
7. **`READINESS.json` has redundant keys.** `clean_environment_install` and `current_clean_environment_install` duplicate each other, and two blockers overlap. It has no schema check.

**From code reading, not executed**

- **`digest()` is not RFC 8785.** `digest({"a":1})` should differ from `digest({"a":1.0})`, and float formatting follows Python `repr`. That is a cross-language durability risk.
- **`calibrate_false_alert_threshold` accepts a string for IDs.** `calibration_ids="abc"` is exploded into characters when the length matches.
- **`state_hash` reads a private sklearn attribute** (`_fit_X`). It works on 1.8, which the passing test confirms here, but it is fragile.
- **Score-B pooling includes unobserved tokens.** `get_pooled_embedding` takes `mean(dim=1)` with no padding mask, so embeddings can encode missingness patterns. The plan already requires a missingness-only baseline, which is the right guard.
- **Out-of-sample scope is not enforced for the combiner or calibration.** `FrozenScoreCombiner` and the calibrator check lake IDs only, not that the scores are out-of-sample relative to the encoder and kNN bank. Plan §4.1 discloses this as a caller responsibility.

## Going One Step Further

Make provenance structural instead of declared. Every scope guard today checks caller-supplied lake IDs, never data. The fix is cheap: have `FeatureNormalizer.fit` return a state that includes per-lake content hashes. Then require scorers, the combiner and the calibrator to accept only objects carrying that `state_hash`. Out-of-scope fitting then fails by construction, which turns WP04/WP06 lineage from prose into a primitive. Pair it with the `finite_vector` decoupling from finding 2.
