# Release scope and limits

`READY_FOR_HUMAN_SUBMISSION_REVIEW` means the current frozen evidence passed implemented local checks and a required evidence-bound review was recorded. The local assurance level is `STRUCTURALLY_VALIDATED`. Neither field establishes scientific truth, external validity, causal identification, novelty, or venue acceptance.

Ed25519 signatures are verified and bound to the plan, snapshot, runtime and outputs. The local signer and experiment share an OS user. That user can access its signing key and evaluation files, alter the gate, or omit experiments outside the workspace. This implementation therefore cannot claim `SUPERVISOR_ATTESTED`, `SEALED_EVALUATION_ATTESTED`, or independently verified review. It would need an external trust boundary and independently pinned identity to make those claims.

The gate validates provenance manifests as author declarations and detects inconsistencies; it cannot prove truthful acquisition, representative sampling, real device telemetry, calibrated sensors, scientific operator semantics or honest agent reasoning. Cold review, raw evidence inspection and domain expertise remain necessary. Fresh sessions and different models are disclosed rather than inferred to be independent.

The archive verifier checks membership and SHA-256 bytes. A signed handoff manifest authenticates metadata and membership only against a separately trusted public key. Without that pin, checksums establish byte consistency only and an owner can rewrite a manifest together with its contents. A relocated archive passing integrity verification has not necessarily been re-audited, and cryptographic receipt checks need a trusted public key. Handoff does not modify the proprietary license or grant redistribution rights.

Group-paired comparisons quantify test-group uncertainty conditional on trained models. Seed-only comparisons quantify training randomness on a fixed corpus and cannot establish population-level superiority. Small samples, bootstrap interval coverage and domain-specific dependence require scientific assessment beyond fixed floors.

Execution history uses a signed local ledger: an attempt is reserved before launch and its execution-record digest is committed afterward. The audit checks exact attempt membership, and amendments commit prior epoch file inventories. Deletion or alteration relative to those current signed records blocks. This is not an external append-only witness: a same-user operator can restore an entire earlier valid signed state. Local signatures cannot establish monotonic history or exclude experiments conducted elsewhere. Preserved test sample/source/group identities disclose overlap, but wholesale relabeling or acquisition fraud still requires external provenance review.

Bundle verifiers cap archives at 100,000 members and 8 GiB total declared uncompressed size. Creation uses fixed ZIP timestamps and regular-file permissions so identical metadata and contents yield identical bytes. Original frozen source/data bytes are not copied into historical epochs; prior hashes, plan snapshots, output files and receipts remain, while only the current frozen inputs can be reconstructed from the handoff.

Project publication checks inspect staged and outgoing Git bytes, messages and reachable history using a private local policy. The public allowlist excludes engine/evidence/procedure files; private reviewer handoff ZIPs are not public releases. Binary approvals record review of exact artifact bytes. Hooks and lexical checks reduce accidental leaks but cannot prove semantic cleanliness, enforce policy against their owner, inspect Git LFS object bytes or govern external GitHub issue/PR/upload content. Non-Git evidence workspaces have no publication assurance.
