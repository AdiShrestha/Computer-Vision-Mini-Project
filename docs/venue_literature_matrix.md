## Baseline and novelty consequences

The minimum Sentinel-GL comparison shortlist remains:

1. an operational lake-extent or physically interpretable change rule;
2. CUSUM or another non-learned statistical detector;
3. Isolation Forest;
4. One-Class SVM; and
5. a learned temporal autoencoder/representation comparator.

All rows must use the same task instances, information budget, calibration isolation, missingness policy, and prediction-ledger schema. A method that cannot accept the same input or label definition must be reported as non-comparable rather than silently omitted or ranked.

The closest defensible contribution may be evaluative and evidence-oriented: authentic multi-sensor acquisition, a leakage-safe common-instance protocol, and a transparent negative result under event scarcity. Architecture novelty alone is not assumed. The matrix therefore seeds the following pre-manuscript questions:

- Is the final comparison against current learned and classical methods genuinely common-task?
- What is the independent unit: lake, event, or another declared cluster—not overlapping window count?
- Which cloud/missingness strata are observed rather than imputed or filtered away?
- Can the final claim survive if the learned model does not beat the simpler baselines?

No venue alignment, baseline sufficiency, or MAR gate is marked resolved here.
