## New evidence-backed findings

**1. Bare-string lake IDs bypass the calibration/evaluation overlap guard (Medium, executed).**

```python
from sentinel_gl.calibration import calibrate_false_alert_threshold as cal
cal([1.,2.,3.], ["lakeA","lakeB","lakeC"], ["lakeA"], .4)  # raises: calibration overlaps evaluation
cal([1.,2.,3.], ["lakeA","lakeB","lakeC"], "lakeA", .4)    # returns threshold 3.0, no error
```

A bare string is exploded into characters, so `'lakeA'` becomes `('l','a','k','e','A')` and never overlaps. `calibration_ids="lakeA"` with five scores is likewise accepted. Plan §4.1 treats IDs as caller-trusted, but even under that model a string should be rejected. `FitScope` already requires a tuple, so the same concept is validated inconsistently. The fix is to reject `str`/`bytes` and share one ID validator.

**2. Factory credential scrubbing is a denylist (Medium, executed).** `execution_env` strips `FACTORY_SUPERVISOR_KEY`, `AWS_*`, `CDSAPI_*`, `EARTHENGINE_*` and two Google names. With fake values set, `GITHUB_TOKEN`, `ANTHROPIC_API_KEY`, `EARTHDATA_PASSWORD`, `CDSE_PASSWORD`, `ASF_PASSWORD`, `COPERNICUS_PASSWORD`, `NASA_EARTHDATA_TOKEN`, `HF_TOKEN` and `SSH_AUTH_SOCK` all reached the worker. That is a gap against plan §9.3 ("sanitize from credentials") and the FU12 description, because Earthdata, CDSE and ASF are the providers this project targets. An allowlist that fails closed is the deterministic form.

**3. The two core operators don't compose as shipped (Low-Medium, executed, disclosed).** A single late-available row early in a context gives `trailing_windows` decision dates `['2023-01-20','2023-01-07','2023-01-10']`. `first_sustained_alarm` rejects them ("must be strictly ordered"). §4.1 discloses that a scheduler is needed, but it is specified, not implemented, and no test covers the chain.

**4. Hardware claims are not disabled in code (Low-Medium, from code).** `audit.hardware()` accepts durations and memory from a project-written `hardware_trials` table. It never joins them to the supervisor receipt telemetry that FU11 repaired. The audit's own `not_automated` list discloses this, so the plan's "remain disabled" is policy, not enforcement. It is mitigated here because the `binary_classification` profile blocks the whole Sentinel-GL plan. A cheap deterministic check is to require that the sum of trial durations not exceed the receipt's measured wall time.

**5. `digest` is not canonical across number types (Low, executed).** `digest({"a":1}) != digest({"a":1.0})`, while tuples and lists hash identically. It is stable in Python but not a cross-language RFC 8785 digest.

**6. Plan wording nuance for F10 (Low).** The claims reproduce against the legacy tag: `SEED = 42`, `CosineAnnealingLR(T_max=10)`, and checkpoint selection on training loss. But normalization was computed from training-role lakes only (INV-002), and its `dates` parameter is never used. So the defect is purely temporal, and the plan should say so rather than imply broader leakage.
